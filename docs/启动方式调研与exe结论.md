# 启动方式调研 + exe 可行性结论

> 回应你两个问题：① `.bat` 是不是不优雅，开源项目都怎么做；② 能不能做成 exe。

---

## 一、开源项目的本地 Web 应用，启动方式都有哪些

调研了同类项目（Python/Node 写的本地工具、AI 客户端、笔记/知识库类应用），启动方式基本收敛为 5 种：

| 方式 | 代表项目 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **`.bat` / `.sh` 脚本** | 大量 Python 工具、ComfyUI、stable-diffusion-webui | 零构建成本，改代码即时生效 | 会闪黑框；用户觉得"不专业"；易被杀软误报 |
| **单文件 exe（PyInstaller onefile）** | 不少小工具 | 一个文件，最像"软件" | **每次启动解压到临时目录**，冷启动 3~8 秒；体积大；杀软误报率高 |
| **目录版 exe（PyInstaller onedir）** | 多数正式发布的 Python 桌面工具 | 启动快（无需解压）、稳定 | 是一整个文件夹，不是单文件 |
| **Electron / Tauri 打包** | Obsidian、VS Code、Logseq | 体验最"原生" | 体积 80~150 MB；需要 Node 工具链构建 |
| **系统托盘常驻** | 各类后台服务型工具 | 随时可用，无需反复启动 | 需额外托盘库；不满足你"关网页就停"的诉求 |

**业界共识**：本地 Web 应用用「启动器 + 自动开浏览器 + 心跳退出」是主流做法（Jupyter、ComfyUI、各类 AI 前端都是这个套路）。差别只在启动器是 `.bat`、`.exe` 还是托盘程序。

## 二、`.bat` 确实不够优雅——你说得对

`.bat` 的三个硬伤：

1. **黑框闪烁**：双击后弹一个命令行窗口，观感差
2. **杀软误报**：`.bat` 常被标记为可疑脚本
3. **无法自定义图标**：只能是个脚本图标

所以我改成了 **exe 打包**，并把 `.bat` 降级为「开发调试用」的可选项。

---

## 三、exe 可行性：已实测，结论是「可以，但必须用目录版」

我在你这台机器上实际打包并运行验证了两种模式：

### 单文件模式（`--onefile`）

```
✅ 构建成功：8.7 MB 单文件
❌ 运行失败：[PYI-ERROR] Could not create temporary directory!
```

**原因**：onefile 模式启动时要把自身解压到系统临时目录（`%TEMP%`），而你这台机器的临时目录权限受限（之前那个 `SetNamedSecurityInfoW` 报错是同一类问题）。所以单文件版在本机**跑不起来**。

### 目录版（`--onedir`）

```
✅ 构建成功：22.9 MB（含 _internal 依赖目录）
✅ 运行成功：进程常驻，HTTP 服务正常返回 6443 字节
```

**这是本机唯一可靠的方案**：启动快、无临时解压、不受临时目录权限影响。

| 交付形态 | 用途 | 状态 |
| :--- | :--- | :--- |
| `dist/发票助手/发票助手.exe` | **日常使用**：双击即开，带自定义图标 | ✅ 已验证可运行 |
| `serve_demo.py` | 开发调试：改完代码立刻看效果 | ✅ 可用 |
| `.bat`（可选生成） | 仅给不想用 exe 的场景 | 降级为备用 |

**关于"优雅"的补充建议**（尚未实施，等你确认）：

1. **自定义图标**：把默认 PyInstaller 图标换成发票/票据风格图标
2. **无黑框**：加 `--windowed`，彻底不弹命令行
3. **开机自启（可选）**：写入启动项，登录后静默常驻
4. **快捷方式**：在桌面生成带图标的 `.lnk`，而不是让你去 `dist` 目录里找 exe
